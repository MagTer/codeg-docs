# 系统

**设置 → 系统**——在应用中标记为**系统管理**——管理软件更新、开机自启、命令行访问、网络代理、语言，以及数据同步与备份。各部分独立保存，无需页面级的保存。

## 软件更新 {#software-update}

检查所配置的发布来源是否有更新版本的 Codeg，并在可以的地方就地安装它。面板显示你的**当前版本**和一个**检查更新**按钮；检查之后，它会记下时间（*“上次检查…”*），并显示 *“当前已经是最新版本”* 或那个正等待你的发布版本的详情 —— 它的版本、日期和完整的发布说明。

::: tip 你不必特意来找
新版本也会在工作区里主动现身：[状态栏](/zh/guide/workspace#the-layout)会出现一个 **新版本 v…** 徽章，它的浮层里同样有版本号、**更新内容**说明和各项操作。两处读取的是同一次检查 —— 一次拉取同时回答两边，因此它们永远不会说法不一。**稍后**会忽略某个版本，按版本生效并同步到每个打开的窗口，留下一个仍可点击的灰色图标；下一个版本会重新点亮徽章。

**更新说明会用你的语言呈现。** Codeg 每个版本都发布为一份正文，里面装着英文说明、一个分隔线，然后是中文翻译——于是两处界面过去都会给你看你读不懂的那一半，而在一个 320 像素宽的浮层里，那一半正好挡在你和按钮之间。从 **0.25** 起，与你的[界面语言](#language)匹配的那一半会被挑出来：简体中文与繁體中文取中文，其余八种语言取英文。切分点读的是发布格式实际写下的那个分隔线，而不是靠「中文从哪里开始」去猜——因此一份没有分隔线的说明会完整呈现，而不是被截断到两边读者都看不全。
:::

升级按钮的行为取决于你在哪里运行 —— 这是桌面与服务器真正有所不同的唯一界面：

- **桌面应用** —— **升级到 vX** 会下载该发布版本并显示进度条。在 macOS 和 Linux 上，它随后会切换为 **重启以更新**，点击即重新启动进入新版本。在 **Windows** 上没有重启这一步：下载一完成，Codeg 就会关闭，安装程序无需你确认便会运行，并重新打开它。自 **0.36.0** 起，Codeg 会先停掉它的智能体及其 `codeg-mcp` 伴生进程、它的终端和 Web 服务，并记住你打开着的窗口；安装程序会把仍在使用中的文件挪到一旁 —— 过去，更新正是因为这样的文件而在 `codeg-mcp.exe` 上以 *Error opening file for writing* 中断；而如果安装程序启动不了，Codeg 会以你原来的那个版本重新启动。
- **可自更新的服务器** —— 支持就地更新的独立 `codeg-server`（或 Docker）行为相同：下载、进度、重启。关于服务器更新如何工作，见[部署](/zh/getting-started/deployment)。
- **任何无法自更新的情况** —— 较旧的远程服务器会回退到一个 **查看 vX 发布** 按钮，它会打开 GitHub 发布页面，让你手动更新它。

**安装包必须是为所提供的那个版本签名的。** 自 **0.36.0** 起，无论是桌面应用还是服务器的在线升级，Codeg 都只在更新包的签名写明的恰好是该发布所宣告的那个版本时才安装它 —— 这样，一个较旧的已签名安装包就没法冒充成较新的版本。没通过这项检查的安装包，只会显示一句笼统的 *安装更新失败*。

**0.38.0** 还修复了两类重启问题：macOS 会等待旧实例退出后再启动新实例，让 Dock 保持一个图标；Windows 安装器改用 Windows API 停止随附 helper 进程，避免 WMI 查询导致更新一直卡住。

::: info 回滚（仅限服务器）
可自更新的服务器会保留上一个二进制文件，因此升级之后会出现一个 **回滚** 按钮 —— *“恢复到上次升级前所安装的版本。”* 它是为那种只在后来才浮现的回归而准备的 —— 也就是在自动的试用窗口检查早已通过之后。桌面应用通过操作系统的安装程序更新，不提供这一项。在 **Docker** 上，就地升级只在容器被重建之前有效 —— *“若要保留它，请拉取或构建新版本的镜像并重建容器。”*
:::

**写不进自己安装位置的服务器，会在你动手之前就说出来。** 自 **0.32.1** 起，可自更新的 `codeg-server` —— 在 Linux 或 macOS 上 —— 会提前检查它能否同时写入二进制文件所在的位置和 Web 文件所在的位置。写不进时，面板会用琥珀色指出是哪个目录，如果系统给出了原因（比如磁盘已满）也会一并说明；升级按钮会变成 **查看 vX 发布**，让你手动更新，而在有新版本可装期间，状态栏的更新浮层也会这么说。过去它会一路走到安装那一步，然后只丢下一句光秃秃的*请关闭应用后重试*。除非问题出在缺少权限，**回滚** 仍然可用。

如果检查或安装失败，原因会就地显示 —— 无法访问的更新来源、网络错误，或下载或安装失败 —— 通常是连接性问题，下面的代理面板可以处理它。被上面的版本检查拒绝的安装包也会落到这里，显示为安装失败。

## 开机自启 {#launch-at-login}

**0.27** 新增的一个开关：*“登录这台电脑后自动打开。”* 仅限桌面端，在 **macOS、Windows 和 Linux** 上一样可用。在 macOS 上它注册的是一个 Launch Agent，所以打开它不会触发「自动化」权限提示。

Codeg **不保存这个设置的任何副本** —— 操作系统自己的启动项就是这个设置，开关是从它那里读回来的。这带来一个具体的差别：之后开关显示的是**系统最终认可的状态**，而不是你请求的状态。如果 Codeg 之外的什么东西否决了这个启动项 —— 通常是 Windows 任务管理器的启动标签页 —— 开关会翻回关闭，而不是声称一个机器并不认同的状态。如果这个启动项根本读不到，面板会直说，而不是去猜。

在 **macOS** 上，一个随登录自动打开的 Codeg，如果更新是从 **0.35.2 或更早版本**发起的，更新之后可能不会自己回来 —— 点一下它的 Dock 图标就能打开。从 0.36.0 起发起的更新会正常重新启动。

## 命令行访问 {#command-line-access}

**0.38.0** 新增的**命令行访问**允许本机的 **`codeg-cli`** 命令通过这个 Codeg 运行提示词，**默认开启**。卡片会显示用于发现当前实例的私有**发现文件**路径和一条**示例**命令。若监听器未能启动，则显示原因。

关闭后，本地监听器立即停止，发现文件也会被移除。它**不会**关闭服务器的认证 HTTP API：携带服务器令牌的 `codeg-cli --url …` 仍然可用。监听器的密钥在每次启动时生成，存放在仅所有者可读的文件中；以你的操作系统用户身份运行的程序均可使用它。→ [隐私与安全](/zh/reference/privacy#command-line-access)

在**本地桌面应用**中，**安装命令行工具**会将随附命令放到 PATH 上：macOS 在 `/usr/local/bin` 创建链接，Windows 将安装目录的 `bin` 文件夹加入用户 PATH，AppImage 则在 `~/.local/bin` 创建链接。Linux `.deb` 和 `.rpm` 安装包已经提供该命令。其他安装提供的现有命令会被保留；若有冲突，卡片会说明原因。Windows 安装后需打开新终端。浏览器和远程工作区会话不提供这个本地安装按钮。

安装、实例选择、权限策略、结构化输出和 CI 用法见[命令行](/zh/guide/command-line)。

## 网络代理 {#network-proxy}

将 Codeg 自身的网络流量通过代理路由。勾选 **启用系统代理** 并输入一个 **代理地址**；此后，*“后续的网络请求会优先使用此代理（包括 ACP 聊天、智能体安装和 Git 远程操作）。”*

该地址接受一个 `http`、`https` 或 `socks5` URL —— 占位符是 `http://127.0.0.1:7890`，一个典型的本地代理。**代理启用后它是必填的**（打开代理而不填地址会被拒绝），且该设置**随手保存** —— 切换复选框或离开该字段都会提交它。它仅在 *启用系统代理* 打开时生效；取消勾选即可重新直连。

**不写协议头，Codeg 会替你补上。** 光写 `127.0.0.1:7890` 从前也能通过校验并被原样存下 —— 更新和二进制下载还扛得住，但 **npm 会拒绝每一次智能体安装**，只丢下一句光秃秃的 `ERR_INVALID_URL`，完全看不出原因。从 **0.28** 起，没有协议头的地址会在保存时、以及再次交给子进程时被规范化为 `http://`，而已经写明协议的地址则原样保留，因此 `socks5://` 代理绝不会被改写。旧版本存下的值会在读取时被修好。从 Codeg **外部**设置的代理 —— `docker -e`、shell export —— 则刻意保持你写的样子；如果 npm 因此报错，错误信息会点出是哪个变量，而不必你自己去找。

**不走代理的地址** 列出哪些目标应当直连 —— 这是 **0.32.2** 新增的。各条目之间用逗号分隔、不加空格：`example.com` 匹配该域名，`.example.com` 匹配它的所有子域名，IP 地址也可以。本机地址 —— `localhost`、`127.0.0.1`、`::1` —— 总是直连，无需列出。该字段在你离开它时保存；代理开启期间，这份列表会以 `NO_PROXY` 环境变量的形式生效，对 Codeg 以及它启动的每一个智能体都是如此。列表里任何位置出现 `*`，都表示*全部绕过代理*，此时 Codeg 会只传一个 `*` 出去，因为 Python 和 curl 只在 `*` 是整个取值时才认它。

::: warning `*` 对 Antigravity 1.3.0 及更高版本不再完全生效
**Antigravity 1.3.0** 及更高版本——自 **0.37.0** 起固定的是 **1.4.1**——只要设置了代理，都会自己把本机地址追加进 `NO_PROXY`。这会把单独一个 `*` 变成 `*,localhost,127.0.0.1,::1`——一个列表，而 Python 会跳过列表里的 `*`。所以在配置了代理、而这份列表里（或者你自己导出的 `NO_PROXY` 里）有 `*` 时，Antigravity 自己的一部分请求——它的 Python 服务发出的那些——会重新**走代理**。想让它们保持直连，就把它们需要访问的主机逐个列出来，而不是写 `*`。
:::

这条本机例外同样适用于你从 Codeg **外部**设置的代理，也正是它让 **OpenCode** 和 **Antigravity** 在代理架设于另一台机器上时依然能用：两者都要和各自的一个本地服务通信，而在 **0.32.2** 之前，这些连接也会被送进代理，结果以 *OpenCode service failure* 或 *Failed to connect to WebSocket* 失败。

这就是承载 Codeg 一切对外请求的代理 —— 你的账户所认证的 [Git 操作](/zh/reference/settings/version-control)、智能体安装、模型流量。若要在应用启动*之前*从环境中设置代理，见[配置](/zh/getting-started/configuration)。

## 语言 {#language}

设置 Codeg **自身界面**的语言 —— 菜单、按钮、设置。**应用语言** 可以是 **跟随系统** 或十种之一：英语、简体中文和繁体中文、日语、韩语、西班牙语、德语、法语、葡萄牙语，以及阿拉伯语。跟随系统区域设置时，*“不支持的语言会回退到英语。”* 该选择立即生效并被记住。

（这是桌面或浏览器应用的界面语言 —— 与任何单个对话的语言，或本文档站点的语言无关。）

## 数据与同步 {#backup-restore}

*“「配置同步」在设备之间搬运设置；「备份」打包这台设备上的全部 codeg 数据。”* 共三个标签页，默认打开第一个：**配置同步**、**备份** 和 **恢复**。

### 配置同步 {#configuration-sync}

把你的设置在机器之间搬运 —— 通过一个文件，或通过你自己的 WebDAV 服务器。和备份不同，它体积很小，从不删除任何东西——它新增条目、更新它匹配到的条目，不去碰它没有提到的——也从不碰你的对话。顶部折叠着的 **同步范围** 列出了两边的内容：

| 包含 | 不包含 |
| -------- | ------------ |
| 模型服务商，**含 API 密钥** | 会话记录与历史 |
| 智能体设置 —— 其中包括每个智能体的环境变量 | 上传的文件与图片 |
| 自定义智能体 | 工作区项目与路径 |
| [助手](/zh/guide/assistants)，自 **0.36.0** 起 | MCP 服务器，归各 CLI 自己管 |
| 快捷消息和任务模板 | 登录凭据与令牌 |
| 应用偏好 —— 语言、浅色或深色、缩放、关闭按钮行为、日志级别、委派设置与智能体默认设置、大部分会话内工具开关、聊天频道的默认设置 | |

偏好里*不会*随行的那些，同样是有意为之：主题色、字体、聊天宽度以及「外观」里的其余设置，都保存在各个浏览器或窗口里；[浏览器操作和电脑操作的开关](/zh/reference/settings/collaboration#in-conversation-tools)留在它们所操作的那台机器上；而任何与账户或这台机器绑定的东西 —— git 和 forge 令牌、聊天频道凭据、Web 服务令牌、代理、仓库面板的设置和 webhook 密钥 —— 都绝不会离开。

**配置文件。** **导出到文件** 会写出一个 JSON 文件 —— `codeg-config-<time>.codegcfg.json` —— 供你带到另一台机器上；**从文件导入** 会先显示文件里有什么、每一类各有多少条，并在应用之前先征求你的确认。无论下面的 WebDAV 开关怎么设，这个文件都**从不加密**，而且里面有你的 API 密钥 —— 请像对待密码一样对待它。

**WebDAV 同步** 默认关闭，它会把同一份快照上传到你选择的服务器：

- **服务商** 可以替你填好 **坚果云**、**Nextcloud** 或 **群晖 NAS** 的地址，也可以保持 **自定义**。接下来是 **服务器地址**、**用户名** 和 **密码** —— 服务提供应用密码的，就填应用密码 —— 以及 **远程目录**（`codeg`）和 **配置集**（`default`）。使用同一个配置集的机器共享同一份配置；工作和个人的机器请用不同的配置集。文件会落在 `<server>/<folder>/v1/<profile>/` 下。
- **加密快照** 默认关闭，它用一个 **加密口令** 保护上传的内容，参与同步的每台机器都要使用同一个口令。不开启时，一条琥珀色提示会如实说明：快照以明文上传，API 密钥也在其中，所以请只使用只有你能访问的服务器。
- **自动上传** 默认开启，每 **5**、15、30 或 60 分钟检查一次 —— 除非你改动，否则就是 5 分钟 —— 并且只在配置发生变化时才上传。
- **保存** 会存下这些设置。**测试连接** 用表单里当前的内容去试，但不保存。**立即同步** 会马上上传，**从远程恢复** 则下载并应用 —— 两者用的都是*已保存的*设置，所以请先保存你的改动。按钮下方是 **上次同步：…**，以及可能出现的 **上次错误：…**。

没有任何东西会被**自动下载**：自动同步只管上传，而从服务器取回一份副本，永远要通过 **从远程恢复**，并先经过一次确认 —— 确认框会写明这份副本来自哪台机器、是什么时间上传的。同一配置集上的机器覆盖的是同一份副本，所以最后上传的那台说了算。

**应用**一个文件或一份远程副本时，**只新增和更新，从不删除** —— 快照没有提到的条目会原样保留。传入的助手如果与本机已有的某个助手重名，会被改名为 *名称 (2)*。外观、语言和服务商列表要在重启 Codeg 之后才会生效。格式比当前 Codeg 能读的更新的快照，会在写入任何东西之前就被拒绝——更新版本的 Codeg 写出的同一格式的快照则没有问题；来自较旧 Codeg 的快照，则只是不去碰它没有携带的那些内容。

**撤销导入** 在有东西可撤销之后才会出现。每次导入、每次从远程恢复和每次撤销之前，Codeg 都会尝试把当时的配置保存下来 —— 最近十份，放在 `~/.codeg`（或 `CODEG_HOME`）下的 `config-snapshots/` 里，是含有密钥的明文 JSON —— 而 **撤销** 会把其中一份放回去。它用同样的合并方式重新应用那份副本，所以各项的值会回到原来的样子，但那次导入*新增*的条目会留下来。如果那次保存失败，导入照样会进行，只是没有可以用来撤销的东西。

WebDAV 密码和加密口令从不属于快照的一部分：在桌面端，它们保存在操作系统的钥匙串里；在 `codeg-server` 上，则保存在服务器自己的机密存储里。如果你改了服务器地址或用户名，并在密码栏留空的情况下保存，已保存的密码会被丢弃，而不会被发给新的主机。在连接到远程工作区的桌面窗口中，这个标签页操作的是**服务器的**配置。

### 备份 {#backup}

这台机器上整个 Codeg 安装的便携快照 —— *“把这台设备的 codeg 数据（数据库与上传文件）打包成一个归档文件。”* 配置同步搬运的是设置、并把它们合并进来；而备份搬运的是一切，恢复则会整体替换。

导出会写出一个包含你的**数据库和上传内容**的 `.codegbak` 归档文件。有两个选项来塑造它：

- **包含会话内容** *（默认关闭）* —— *“同时归档智能体 CLI 的会话记录（Claude、Codex、Gemini……）。会增大体积。”* 关闭时，备份只是你的 Codeg 数据；打开时，它还会拉入底层智能体 CLI 各自的会话记录文件。自 **0.35.0** 起，这也包括 Codex 的会话索引 —— 每个 Codex 对话的**名称**就存放在那里；在此之前制作的备份缺少这份索引，因此从这样的备份恢复出来的 Codex 对话，可能会以它的第一条提示词作为名称。
- **口令** *（可选）* —— 加密归档。留空则 Codeg 会以琥珀色警告 *“此备份将以明文包含机密（API 密钥、令牌）”* —— 因为它确实如此；请把它存放在安全的地方。设置一个，则相反的告诫适用：*“如果你丢失了它，备份将无法恢复。”*

**导出备份** 会构建它 —— 桌面应用保存一个文件，浏览器会话则下载一个。

有些智能体把会话存在 **SQLite** 里，而一个正被打开着的 SQLite 没法简单复制。从 **0.30.4** 起，导出会**点名那些需要特殊处理的**（没被点名就说明普通复制成功了），并写明它遇到的是三种情况中的哪一种：**从一份私有副本中恢复**（完整）、**未连同预写日志一起归档**（最新的消息可能缺失），或者**根本没有归档** —— 因为它在复制过程中一直在变，或者压根复制不出来，而这总好过归档一份撕裂的副本。面板会列出前八条，其余的只给一个计数。在此之前，OpenCode、Hermes、Cursor 和 Antigravity 的数据库可能还原回来时丢掉最新的消息、旁边还躺着一份过期的日志；而**自定义 ACP 智能体**的对话还原回来是在的、却是*空的* —— 它们的消息正文备份和恢复两条路径都没打包。

### 恢复 {#restore}

**选择备份文件**（`.codegbak` 或 `.zip`），Codeg 会在做任何事之前先检查它。如果它是加密的，你会被要求输入口令；然后一个 **备份详情** 卡片会显示它是何时制作的、由哪个应用版本制作，以及它是否**兼容** —— 来自比你正在运行的更*新*的 Codeg 的备份无法恢复。

恢复是一次**完全替换**，面板对此直言不讳，用红色标出：*“恢复会替换所有当前的 codeg 数据（数据库和上传内容）。你的当前数据会先被快照，以便可以恢复。”* 你要通过一个 **替换全部数据？** 对话框确认，之后 Codeg 会暂存恢复并重启以应用它。

动手之前有三件事值得了解：

- **桌面备份不携带你的钥匙串机密。** *“桌面端的 GitHub/聊天令牌存放在你操作系统的钥匙串中，不包含在内；恢复后请重新输入它们。”* 在**服务器**上，这些相同的令牌存放在一个*确实*在备份中的文件里 —— 区别正是[版本控制](/zh/reference/settings/version-control)下所述的那种系统密钥环划分。
- **恢复对话内容是单独的选择。** 如果备份包含了智能体 CLI 的会话记录，你要选择它们落在哪里 —— 跳过它们、把它们放进一个**安全的旁侧文件夹**，或把它们写回**原始的 CLI 位置**（附带冲突扫描和可选的覆盖），好让智能体重新看到它们的历史。
- **有两份会话列表是合并，而不是替换。** Codex 和 Kimi Code 的会话索引 —— 前者为每个 Codex 对话命名，后者记录每个 Kimi 会话属于哪个文件夹 —— 都是 CLI 不断往里追加的只追加文件。自 **0.35.0** 起，恢复到原始位置时，会把备份里那些现有文件不认识的会话条目**追加**进去，而不是把整个文件当作冲突跳过，或是把它覆盖掉；于是恢复出来的对话保留各自的名称和文件夹，正在运行的 CLI 也不会丢失任何东西。打开覆盖时，对于条目内容不一致的会话，也以备份里的条目为准。

#### 恢复前快照 {#pre-restore-snapshots}

那句警告里说的快照不是一种修辞 —— 它是一份列出来、你可以退回去的东西。**恢复前快照**就在恢复控件下方，通常保留**最新的两份**。

带着清单（记录了恢复前哪些东西*不存在*）的快照会提供**回退到这份**；而在这份清单出现之前写下的快照只会列为**仅可查看**，因为没有它，一次回退分不清「这个别动」和「这个本来就不存在，删掉」。回退会用那份快照替换你当前的数据并重启，而让它值得一试的正是这一点：它**在替换的路上，又把被替换掉的数据快照了一份**，所以这次回退本身也是可逆的。

一次恢复也会报告它做了什么，而不是留给你去猜：**恢复已暂存**，并附上因为你没有选择覆盖而被保留的文件数（合并过的会话索引不算在其中）、没能写回的会话数据库数，以及 —— 当有智能体正在运行、它们的会话记录改落到旁侧文件夹时 —— 是哪些智能体、落到了哪个路径。

::: warning 备份作用于这台机器
备份和恢复作用于实际运行 Codeg 的那台机器的数据。如果你身处一个**连接到远程工作区**的桌面应用中，**备份** 和 **恢复** 两个标签页会被禁用，并附注 *“请直接在该服务器上管理其备份”* —— 这里的原生文件对话框与远程服务器的存储对不上。**配置同步** 在那里依然可用，操作的是服务器的配置。
:::

## 值得了解 {#good-to-know}

- **设置各自保存。** 命令行访问、代理、语言、开机自启、更新和数据与同步各自行事——WebDAV 设置有它自己的**保存**；没有页面级的保存。
- **开机自启没有本地副本。** 操作系统的启动项就是这个设置，因此开关显示的是你的机器实际认可的状态。
- **桌面和服务器的更新方式不同。** 桌面应用自动安装并重新启动；服务器就地更新并重启（且可以回滚）；旧的远程服务器只是给你链接到发布页面。同一个面板，三种行为。
- **未加密的备份就是明文机密** —— 每一份导出的配置也是。除非你给备份设了口令，或为 WebDAV 打开了 **加密快照**，否则 API 密钥和令牌都会以明文随行；导出的配置文件从不加密，所以请把它保存在可信之处。Codeg 一般如何处理机密，见[隐私与安全](/zh/reference/privacy)。
- **恢复是替换，但可逆。** 它会整体换入备份的数据库和上传内容 —— 但会先快照你的当前数据，而那份快照会[连同一个回退按钮一起列出来](#pre-restore-snapshots)，因此一次误操作的恢复可以被撤回。
- **代理是应用级的。** 一旦打开，它就同时承载 git、智能体安装和模型调用 —— Codeg 对外的一切都经由这一条路径。
