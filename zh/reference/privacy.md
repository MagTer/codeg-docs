# 隐私与安全

Codeg 是**本地优先**的。你的对话、设置和项目数据都存放在你的机器上；应用**不含任何形式的分析、遥测或追踪** —— 没有 Codeg 账户、中间没有云、也不会向任何地方回传数据。网络**只会被用于你亲自发动的事情** —— 运行智能体、推送到远程、检查更新、你安排好的一次定时扫描。本页确切阐明这意味着什么：哪些留在原地、哪些离开，以及介于其间的机密如何被保管。

## 本地保存的内容 {#what-stays-local}

Codeg 自身存储的一切都位于运行它的机器上，在它的[数据目录](/zh/getting-started/configuration#where-codeg-stores-its-data)里以及 **`~/.codeg/`** 之下（参见[架构](/zh/reference/architecture)）：

- **SQLite 数据库** —— 你的对话、设置，以及账户的非机密元数据；
- 你的**[技能](/zh/guide/skills)**以及你附加到对话中的任何**上传内容**；
- **[Token 用量](/zh/guide/token-usage)**统计——由你磁盘上已有的会话记录算出，与你的对话存放在一起；
- 诊断**[日志](/zh/reference/settings/logs)**。

解析、存储、git 操作和文件处理全都在**设备本地**进行。不存在需要你亲自运行之外的服务器组件：桌面应用将一切保留在你的电脑上，而[自托管服务器](/zh/getting-started/deployment)将一切保留在那台机器上。没有任何东西被上传到 Codeg —— 因为根本没有可上传*去*的地方。

**删除一个对话是把它藏起来，而不是抹掉它。** 那一行会离开侧边栏、不再被提供，但对话和它的消息仍留在数据库里 —— 而这恰恰就是导入窗口能[把它放回去](/zh/guide/aggregation#bring-back-a-conversation-you-deleted)、历史完好的原因。这件事在两个方向上都值得知道：一次你后悔的删除是可以挽回的，而一次你当作销毁来做的删除并不是。任何读得到数据目录的人，仍然能读到你删掉的东西，所以想真正摆脱一个对话的内容，办法和那个目录里其他所有东西一样 —— [把这个目录本身当作边界](#where-secrets-are-kept)。无论如何，智能体 CLI 自己那份会话记录是磁盘上另一份独立的副本，Codeg 的删除从来就没碰过它。

**HTML 预览拉进来的东西不会越出工作区。** 当 HTML 预览加载它的标记里点名的图片、样式表和脚本，或者网页端上传写入文件时，Codeg 会解析出真实路径，并拒绝任何落在你打开的那个文件夹之外的目标。符号链接本是这道防线最容易被绕过的地方，因此它们会与[你自己关联进来的文件夹](/zh/guide/workspace#work-across-several-folders)逐一比对——只有这些会被跟随，其余一概不跟。你克隆下来的某个仓库即便自带一条 `secrets -> ~/.ssh` 和一个 `<img src="secrets/id_rsa">`，也没法让 HTML 预览读到那个文件：因为没有人点过任何东西。**Markdown** 预览不受这条规则约束——它显示的本地图片，是按下文「你自己打开的文件」那样读取的——但它不运行任何脚本，所以它读到的东西只留在你眼前的预览里。

**你自己打开的东西，指向哪里就去哪里。** 你在文件树里点的文件、回复里的文件徽章、你打开的 PDF 或图片、从文件标签页头部发起的下载——这些都是你主动要求的读取。在文件树里选中的路径会按字面检查——不允许绝对路径，也不允许 `..`——但工作区内的符号链接会被跟随，就像你的终端和智能体会跟随它一样；正因如此，一个符号链接的文件夹才打得开（[#430](https://github.com/spacering-net/codeg/issues/430)）。位于所有工作区文件夹之外的文件，比如智能体输出在 `/tmp` 里的东西，同样能打开，而且自 **0.35.2** 起，浏览器也能下载它。所以在服务器上，持有令牌的人能读取服务器自身进程能读的任何文件——这并不比在那里运行一条命令已经给他们的更多。

从 **0.25** 起，这条严格的规则也覆盖了**删除、重命名和移动**。这三项操作过去只检查目标是不是工作区根目录本身，而一条符号链接可以直接绕过它：树里放一条 `ln -s .. up`，`up/<根目录名>` 就是根目录的第二个名字，删掉它就把整个工作区一起带走了。现在三者都会解析该条目的**父目录**——它们操作的是链接本身，而不是链接指向的目标——并要求它落在工作区之内，已关联的文件夹也算在内。因此，想通过一条你手工做出来的链接去销毁任何东西，都需要*关联文件夹*对话框所提供的那份显式授权；而通过它打开和保存文件则一切照旧。→ [问题 #430](https://github.com/spacering-net/codeg/issues/430)

## 离开你机器的内容 —— 且仅在你采取行动时 {#what-leaves-your-machine-—-and-only-when-you-act}

Codeg 出于少数几个明确触发的原因才访问网络，每一个都是你所做某事的直接结果：

- **智能体 ↔ 模型提供商。** 最主要的一项。当智能体运行时，它的 CLI 会调用你所配置的模型提供商 —— Anthropic、OpenAI 等等 —— 携带提示词以及它所需的上下文。Codeg 编排智能体；**智能体**发起调用，使用在[模型提供商](/zh/guide/authentication)下设定的凭据。它所发送的内容受提供商自身的政策约束，而非 Codeg 的。
- **Git 远程。** 克隆、拉取和推送会与 GitHub、GitLab 或你的远程所指向的任何服务器通信 —— 由[版本控制](/zh/reference/settings/version-control)下的账户进行认证。
- **仓库面板**，如果你使用它。它会针对你选中的那个文件夹调用 GitHub、GitLab 或 Gitea 的 REST API —— *那一个*仓库的 issue 和 pull request，每次都现读，本地不做缓存。只有在你打开了[自动处理](/zh/guide/repository#let-it-pick-items-up-by-itself)之后，它才会自己去读：按你设定的计划做一次扫描，或者由一次 webhook 推送启动的扫描。有两种写操作是可能的。**交付**一个已审阅的任务会推送它的分支——来自 issue 的任务会开一个 pull request，来自 pull request 的任务则推到已有的 head 分支上——而这始终由你来触发。另外，如果*完成后回写评论*开着，每个完成的任务还会发出一条评论——对于自动处理创建的任务，则由自动处理页上它自己的那个开关决定，而那个开关初始是关闭的。→ [仓库面板](/zh/guide/repository)
- **models.dev 价格表。** [Token 用量](/zh/guide/token-usage#what-it-would-cost-at-list-price)依据 models.dev 上的公开目录为你的 token 估价，OpenCode 的设置面板也从同一个文件里列出提供商和模型。打开其中任何一个时，除非有一份不满一天的缓存副本，否则就会重新下载它——这只是一次获取公开列表的普通请求，不携带任何关于你或你的用量的信息。
- **更新检查。** [软件更新](/zh/reference/settings/system)会联系发布源以查看是否存在更新版本——Codeg 开着时它大约每六小时自行检查一次，某次检查失败后至少隔十分钟才会重试，你每次按下**检查更新**时也会检查——若你选择安装则将其下载。
- **安装智能体。** 添加一个智能体 CLI 会从其常规的分发源下载它。
- **电脑操作驱动。** [电脑操作](/zh/guide/computer-use)第一次需要它时——或者你按下**安装**时——Codeg 会从 Cua 项目的 GitHub releases 下载 cua-driver，下载的正是它钉住的那唯一一个版本。
- **聊天频道**，如果你连接了任何频道 —— 这些集成会与你所关联的消息服务通信。
- **你自己写的自定义 CSS 里的远程 `url()`。** 如果你打开了[自定义 CSS 编辑器](/zh/reference/settings/appearance#custom-style)，并粘进一条从网上取字体或图片的规则，那么应用它就会发出那次请求。Codeg 会直接剥掉 `@import`，并在编辑器里对远程 `url()` 给出提示，但不会替你移除它——那是你的样式表。

- **你在[内置浏览器](/zh/guide/browser)里打开的页面。** 浏览器标签页与它所在的站点通信，就像任何浏览器一样，除此之外不与任何人通信——只有一个例外是你自己放进去的：标签页会走**设置 → 系统**里配置的[网络代理](/zh/guide/browser#browsing-data-cookies-and-the-proxy)，和 app 其余部分一样（macOS 14 之前的版本除外，那里浏览器标签页根本无法走代理——配置了代理时标签页会直接打不开，而不是绕过它）。桌面端不存在任何属于 Codeg 自己的中间环节。（浏览器会话里的[端口桥](/zh/guide/browser#in-a-browser-session-the-port-bridge)*就是*一个代理——这是设计使然，因为那是你的浏览器触及服务器回环地址的唯一途径；而在连接到远端工作区的窗口里，远端主机的地址会经由[其服务器承载的一条隧道](/zh/guide/browser#in-a-remote-workspace-window)，从那一端出去。）它保留什么、智能体能看到什么，见下一节。

这就是全部清单了。其中没有任何一项会针对你的文件定时运行。确实有两项是按时钟运行的——更新检查，以及你打开之后仓库面板的定时扫描——而两者问的都是服务器*那一侧*的事：有没有新版本，issue 里写了什么。其余每一项都是在响应你做过的某件事：你按下的某个按钮、你打开的某个页面、你启动的某个智能体。

## 内置浏览器 {#the-built-in-browser}

浏览器是 Codeg 里唯一一处按设计就要渲染别人代码的地方，所以它的边界值得明说。→ [内置浏览器](/zh/guide/browser)

- **浏览数据留在本地，且按配置文件分开。** Cookie、缓存与站点存储与 Codeg 自身的数据分开存放——macOS 14 及以上还有独立存储——这份存储不会被上传到任何地方；至于 cookie 本身，它照常会发给设置它的那个站点，和任何浏览器一样。每个配置文件的数据可以单独清除，删除配置文件会一并删掉它的数据。Codeg 自己**不保留浏览历史**，只记住每个打开的标签页当时所在的地址——重启后标签页能回来靠的就是这个。不过地址确实会进入[诊断日志](/zh/reference/settings/logs)：页面加载记在 *debug*，被规则阻止的跳转与弹窗记在 *info*，因此磁盘上的日志文件可能点出你访问过的站点。
- **智能体只看得到你共享的那些。** [工具组对每个智能体默认关闭](/zh/reference/settings/collaboration#in-conversation-tools)——那个开关才是闸门。授权随后覆盖**一个标签页和一个 origin**，页面离开那个 origin 即结束。在标签页被共享之前，智能体能知道的只有它的 **origin**——因为你要做决定就得看见它——而不是它的标题或任何内容。
- **智能体对某个页面做过什么，就记在那个页面的标签页上。** 读取、动作、被拒，一视同仁，你可以往回翻。两个例外没有标签页可以承载记录、或者压根不发生在某个页面上：*成功*关闭标签页（被拒绝的关闭会记），以及列出当前打开了哪些标签页。
- **智能体自己的 JavaScript 需要一个专属开关，而那个开关就是决定本身。** `browser_eval` 在共享之上还被卡了两道：一个出厂**关闭**的开关，以及标签页共享为*可读可操作*——两道都在后端强制执行，智能体够不着。自 **0.31.1** 起，通过这两道之后代码会**不再逐段询问**就运行：那个逐段弹出的对话框此前是无条件的、答案从不被记住，最终只会被条件反射答掉，所以这个问题被上移到了开关那里。每一次运行仍会写进那个标签页的智能体活动，而**设置 → 浏览器操作 → [在页面上运行代码](/zh/reference/settings/browser#running-code-on-a-page) → 每次都问我**可以把每段代码重新摆回你面前。
- **常驻共享默认是开的——这一条值得想清楚。** **默认共享级别**出厂是*可读可操作*，因此一旦智能体拿到了工具组，标签页每到一个站点——包括智能体自己打开的那个——都会在加载时被共享，跨站跳转也是静默重新授权、不弹提示条。但它*不会*覆盖你：标签页会记住你把每个站点留在了什么级别，所以你停掉共享的站点依旧未共享，你收窄过的站点回来也还是那个更窄的级别——在那个标签页活着的期间有效，这份记忆不跨重启保留。如果你希望每一次共享都是一次明确的动作，请把它设为*不共享*。→ [让智能体在页面上干活](/zh/guide/browser#let-an-agent-work-on-the-page)
- **本地 HTML 文件不是网页。** [文档视图](/zh/guide/browser#html-files-the-document-view)在你为某个文件启用脚本之前不跑脚本、不联网，即便启用也被限制在该文件自己的文件夹内；只要它用到的任何文件在你批准之后发生变化，它就退回安全模式；而且它永远不可共享给智能体。
- **管理员可以替所有人定下来。** 一个[策略文件](/zh/guide/browser#rules-set-by-an-administrator)可以阻止某些主机、也可以整体关闭内置浏览器，用户自己的规则解除不了它。
- **远端工作区的标签页从远端主机发起连接。** 在连接到[远端工作区](/zh/guide/browser#in-a-remote-workspace-window)的桌面窗口里，远端主机自己的地址会经由其 `codeg-server` 承载的一条隧道打开，由该服务器的令牌把关——可以访问服务器能访问到的任何地方，除非服务器的运维者用 `CODEG_BROWSER_TUNNEL` 收窄了范围。隧道在这台电脑上的一端，是它回环地址上的一个代理，没有属于自己的密码：隧道开着的时候，同一台电脑上的其他账户可以借它访问远端主机的网络，和任何回环端口转发一样。在这样的窗口里，智能体永远拿不到浏览器——它们运行在远端主机上。

## 电脑操作 {#computer-use}

[电脑操作](/zh/guide/computer-use)是唯一一个让智能体看到你屏幕上 Codeg 之外内容的功能，这让它的边界成了最需要仔细读的那一组。

- **它默认关闭，开启后也什么都不共享。** 开关出厂是关闭的。打开后，智能体可以列出你的应用和窗口——在你共享之前看不到窗口标题——而在你从状态栏把窗口共享为*仅读取*或*读取并操作*之前，**任何**窗口都读不到。所有这些检查都由 Codeg 在每次调用时进行，没有一项交给智能体自己。
- **有些窗口永远不能共享。** Codeg 自己的窗口——能操作 Codeg 的智能体可以替自己批准请求，或给自己共享更多窗口——以及永不共享名单上那些应用的窗口：默认包括密码管理器，以及系统设置和系统的密码弹窗。共享整个屏幕时，它们会被遮盖，Codeg 无法识别的任何东西也一样。
- **秘密字段不进辅助功能树。** 在窗口的辅助功能树里，被系统标为秘密的字段，其值读出来是 `[redacted]`，智能体也不能往里输入或给它设值。不过**截图**终究是一张画面：以明文显示的秘密会出现在截图里，所以别在窗口显示着秘密时共享它。剪贴板也是你的：智能体只能粘贴或读回它自己放上去的内容——永远碰不到你复制的东西。
- **共享会结束。** 窗口关闭或其应用退出时；默认闲置 30 分钟后；一次**停止**时——它还会中断任何进行到一半的操作，并忘掉智能体放到剪贴板上的内容，之后都无法再粘贴；以及 Codeg 退出时，因为共享的任何信息都不会写入磁盘。
- **它做过什么都列得出来。** 状态栏弹层里的*最近活动*会列出每一个操作，被拒的也算在内，连同对应的应用和结果；悬浮停止条写明共享了什么，还有一个标记显示操作落在了哪里。
- **在 macOS 上，这些权限不属于 Codeg。** 辅助功能和屏幕录制属于 `codeg-computer-helper`——一个独立的应用，在 Codeg 的签名发布版里只应答 Codeg——因此智能体的 shell（它运行在 Codeg 之下）用不了它们；如果 Codeg 自己持有其中任何一项，它会提醒你。**Windows 和 Linux 没有对应的机制。** 在那里，你运行的任何程序都能截取屏幕、发送输入，智能体的 shell 也不例外；这些设置约束的只是智能体*通过 Codeg* 所做的事。
- **驱动版本是钉死的。** cua-driver 只按一个版本下载，并用编译进 Codeg 的 SHA-256 摘要校验——解包前一次，每次启动前再一次；在 macOS 上还会校验它的开发者签名。你无法换成别的版本。
- **窗口里会有别人写的文字。** 另一个浏览器里的网页、一封邮件、一份文档——这些工具会告诉智能体，把窗口显示的内容当作数据，绝不当作指令；但共享仍然是一条让不是你写的文字抵达智能体的途径。只共享任务需要的东西，在确实需要操作之前，优先用*仅读取*。→ [提示词里来自陌生人的文字](#text-from-strangers-in-a-prompt)
- **在服务器上，这由运维者决定。** `codeg-server` 只有在以 `CODEG_COMPUTER_USE=1` 启动时才提供电脑操作，而一旦提供，任何持有其令牌的人都能从浏览器共享那台机器的窗口。桌面应用自带的 [Web 服务](/zh/reference/settings/web-service)永远不会让它所服务的浏览器共享或停止窗口——这些都留在桌面应用里——但那些浏览器启动的智能体运行在桌面上，所以只要开关开着，它们就能拿到这些工具，并使用在那里共享的窗口。

## 仓库可能在你机器上运行的代码 {#code-a-repository-can-run-on-your-machine}

读取一个仓库是安全的，**加载**它则未必。有几个智能体会读取项目自带的配置，而那些配置里可以包含代码——这些代码会在智能体启动时、以你的权限运行，早于你发出任何一条消息。

**Pi 就是出过问题的那一个。** 仓库的 `.pi/extensions` 是一些 JavaScript 模块，其顶层代码会在 pi 启动时执行，而 pi 只会为它信任的文件夹加载它们。到 **0.24** 为止，Codeg 会在启动 pi 之前，把它启动过的每一个文件夹都写进 pi 自己的信任文件——于是「在一个刚克隆下来的仓库里创建或恢复一个 Pi 对话」就足以执行掉它自带的任何东西，没有发出任何提示词、没有权限请求，对话记录里也什么都没有。这次写入落在 pi 自己的文件里，因此它同时也悄悄压掉了独立 `pi` CLI 的信任询问。

从 **0.25** 起，信任是一个显式的、按工作区做出的决定，且只在仓库确实带有受管资源时才询问；对话框会列出每一个文件，并标出会执行代码的那些。旧行为已经写下的授权会**阻止启动，直到你确认它们**——它们会被列出来供你逐条查看和撤销（在 pi 的设置页上），而不是被删除，因为 pi 的那个文件不记录来源，删除它们会悄悄抛弃你自己在 pi 里做出的决定。→ [使用智能体](/zh/guide/agents#pi-project-trust) · [问题 #446](https://github.com/spacering-net/codeg/issues/446)

::: info 沙箱究竟在哪儿
Codeg **自身不提供任何沙箱**。真正约束一个智能体的，是这个智能体自己的配置——Codex 的 `sandbox_mode`、OpenCode 的权限块等等——而这两样如今都能正常生效了：一个被明确设为只读的 Codex 沙箱会让会话以 Codex 的 **Read-only** 模式开始，而自 codex-acp **2.0** 起，这个模式重新做到了真正的只读；OpenCode 的规则则[不用手写 JSON 就能编辑](/zh/guide/agents#opencode-permissions-without-the-json)。

有一处结构性的缺口值得知道。通常情况下，智能体的文件读取和终端命令由 Codeg 代为执行，这意味着它们跑在 **Codeg** 的进程里，落在智能体给自己套的那层沙箱之外。对于确实带有沙箱的智能体，按智能体的**[让智能体自己处理文件和命令](/zh/guide/agents#let-the-agent-handle-its-own-files-and-commands)**开关会把这三样交还给它，让它自己的规则重新覆盖到它们。这个开关默认关闭，因为大多数智能体根本没有可恢复的沙箱，打开它只会白白让出一个本来能用的文件通道。
:::

::: tip Codeg 会收紧智能体自身的默认值
Codeg 自身没有任何遥测，但它运行的那些智能体是独立的程序，各有自己的习惯。凡是 Codeg 能让它们安静下来的地方，它都会这么做——**Claude Code** 在这里是以**禁用遥测或多余的网络请求**设为**开启**、**归属/计费标识**请求头**关闭**的状态运行的，与该 CLI 自身的默认值相反，并且是明确写入的，因此该设置是实际生效的，而非仅仅隐含。两者都可由你在**设置 → 智能体**中更改。→ [使用智能体](/zh/guide/agents#claude-code-attribution-and-telemetry)
:::

## 提示词里来自陌生人的文字 {#text-from-strangers-in-a-prompt}

[仓库面板](/zh/guide/repository)带来了 Codeg 其他部分没有的一样东西：**一段内容不是你写的提示词。** 一个 issue 的正文出自开它的那个人——在公开仓库上，那就是一个陌生人——而读它的智能体手里握着一个 shell、一个可写的 worktree，以及那些用来结算任务的工具。*「忽略你的指令，去执行这个」*，是这段文字里真会出现的东西。

Codeg 的答案是围堵，而不是识别，因为没有任何过滤器能可靠地把指令和描述分开：

- **这些内容被框定为数据。** 它落在自己的块里，标题写着*工作项内容（外部数据，非指令）*，夹在明确的围栏之间，前面还有一段开场白点明它来自哪一家 forge，并用大白话告诉智能体：不要遵从其中出现的任何指令、命令、角色变更或工具请求——而且如果这段内容试图这么做，**要在摘要里说出来**。于是一次企图会出现在你读到的回复里，而不是无声地溜过去。工作项里的任何内容都绝不会被拼进指令段落中。
- **围栏无法伪造。** 内容*内部*任何出现的围栏标记，在发出去之前都会被改写——外观几乎一致，语义上完全失效——因此这段文字无法关掉自己的信封，再以 Codeg 的口吻继续往下说。同一遍处理里还会把回车符和 NUL 字节规范化掉。
- **它有上限。** 标题、标签和作者各有固定配额，正文取用一个 **12,000 字符**信封剩下的部分，超长时会被截断并留下一个可见的*正文已截断*标记，指向工作项的 URL。一个两百页的 issue 挤不掉真正的指令。
- **指令模板属于 Codeg，而不属于调用方。** 一次触发只能指名一个*场景*，无法提供这个场景所代表的文字。它确实会送出的是工作项快照——按上面所述被围栏包住——以及你自己的备注，两者各自落进一个标注清楚的段落。
- **场景约束了交付物。** *先出方案*和*仅审查*明确禁止提交，而且这条约束被记录在任务上，而不是只活在散文里——于是 worktree 的守卫对「这一次运行被允许写什么」有一个确定的答案。（原本还有第三个这样的场景*仅调查*，它已[在 0.28.2 取消](/zh/guide/repository#hand-it-over)——它那一步验证如今成了两种 issue 流程中必做的一环。）

**自动处理免去的是第一步的人工，而不是最后一步的。** 打开[自动处理](/zh/guide/repository#let-it-pick-items-up-by-itself)后，一个陌生人的 issue 可以在没有任何人按下「处理」的情况下到达智能体——这正是它的用途——所以挡在两者之间的就是上面这些措施，而它们全都还在：这是同一条创建路径，有同样的围栏、上限和模板。它做不到的，是跳过最后那一步。它的规则决定接手什么——按标签和作者，*不处理*列表始终优先——所以在公开仓库上，要求一个由你亲手打上的标签（*只处理带这些标签之一的条目*），就能把「是否开始」的决定留在你手里。

还有最后那道兜底，也是最要紧的一条：**由仓库工作项创建的任务，永远不可能在无人看管的情况下合并。** 这不是一个默认关闭的设置，而是一条没有开关的规则。一个设置了[自动落地已审阅任务](/zh/guide/tasks#let-a-folder-land-them-for-you)的文件夹会整个跳过这些行，因为无人值守的落地加上外部撰写的提示词文本，就是一条从陌生人的 issue 通往你主分支的路。来自 issue 的任务仍然可以由**你**点击合并；关键在于必须有一个人来点。而来自 *pull request* 的任务即便如此也不能在本地合并——它的工作会回到那个 pull request 自己的分支上。

还有一条规则方向相反。Codeg 回帖到工作项上的那条评论，**只**由任务 id、结果和 diff 计数拼成——**智能体写的任何文字都绝不会进入别人会读到的帖子**。不是结果摘要，不是提交信息，也不是结论备注。根本没有一个参数能夹带它们，而这正是让这条规则随功能演进仍然成立的原因。

## macOS 文件夹访问提示 {#macos-folder-access-prompts}

在 macOS 上，你可能会看到类似 **"Codeg 想要访问你"文稿"文件夹中的文件"** 的系统对话框 —— 或者是桌面、下载、音乐文件夹。这是 macOS 的标准隐私提示，值得说清楚究竟是什么触发了它。

::: info 是智能体的命令 —— 而非 Codeg 在读取你的文件夹。
Codeg 未声明对这些文件夹的任何特殊访问权限，也不会自行索引或读取它们。该提示之所以出现，是因为**某个智能体的命令在执行你的任务时触碰了一个受保护的文件夹**。
:::

macOS 守护着少数几个个人文件夹 —— 桌面、文稿、下载等 —— 并在任何程序首次伸入其中时发出询问。当智能体运行你任务的某个步骤时，它执行的命令（一个 `find`、一个 `ls`、一个 `grep`、一段构建脚本 —— 或者仅仅是在一个恰好位于这些文件夹之下的项目中工作）可能会越过那条界线。由于 macOS 会将子进程的文件访问归因于启动它的应用，因此该对话框带有 **Codeg** 的名字，尽管真正在伸手的是智能体的命令 —— 这与你自己在 Terminal 中运行那条命令时会得到的提示如出一辙。

如何回应它：

- 若你希望智能体处理该文件夹中的文件，就选**允许**。
- 选**拒绝**，命令便无法读取该文件夹 —— 智能体会照常继续处理其余的一切。

无论哪种方式，选择权都在你手中，而且你随时可以在 **系统设置 → 隐私与安全性 → 文件与文件夹** 下重新调整，那里按应用逐一列出了每一项授权。

## 机密存放在哪里 {#where-secrets-are-kept}

你填进 Codeg 的一切都不会被上传到 Codeg —— 每一份凭据都留在这台机器上。至于留在机器的*哪里*，取决于它是哪一类凭据；而当你把数据目录复制来复制去时，这个区别很要紧。

**在操作系统密钥环里** —— macOS 上的 Keychain、Windows 上的凭据管理器、Linux 上的 Secret Service：

- 你的 [**Git、GitHub、GitLab 与 Gitea 账号**](/zh/reference/settings/version-control)令牌。只有非机密的元数据（服务器、用户名、作用域）与之并排放在数据库里。
- 你的[**聊天渠道**](/zh/guide/chat-channels)凭据。
- 在**无头服务器**上，由于不存在桌面密钥环，这些会回退到数据目录中的一个 **`tokens.json`** 文件，仅在该部署内部可读。

**在 Codeg 自己的 SQLite 数据库里**，未加密 —— 界面上的掩码只是视觉效果：

- [**模型提供商与自定义端点的密钥**](/zh/guide/authentication#where-credentials-are-stored)，以及你为各智能体设置的环境变量，而后者往往正是一个智能体 API 密钥最终的落脚处。
- 一个[**远端工作区连接**](/zh/getting-started/deployment#if-your-proxy-demands-its-own-headers)的访问令牌及其自定义请求头。
- [**Web 服务**](/zh/reference/settings/web-service)的访问令牌。
- 仓库面板的 [**webhook 密钥**](#webhooks-for-auto-processing)，和它的其他设置存放在一起。

**在智能体自己的文件里**，也就是它自己的 CLI 放置的位置：由智能体自行处理的订阅登录或密钥 —— `~/.codex/auth.json`、`~/.grok/auth.json` 等等。

实用的判断标准：**把数据目录当作一份未加密的[备份](#backups)来对待** —— 任何能读到它的人，都能读到中间那一组的全部内容。在[原生移动客户端](/zh/getting-started/installation#mobile-apps)中涉及的凭据只有服务器访问令牌一个，它存放在 iOS Keychain 中，或使用由 Android Keystore 持有的密钥加密。

无论存在哪里，**一个连接的凭据只会去到它自己的来源**——从 **0.28.2** 起，这项比对还包含**协议**，而不只是主机和端口。配置为 `https://box:8443` 的远端工作区不会跟着跳到 `http://box:8443`；仅按主机和端口比对时它是匹配的，而那会把 bearer 令牌连同任何自定义请求头一起以明文送上网络。

::: warning 从前调高日志级别会把连接密钥记下来
Codeg 使用的 WebSocket 库会在 `trace` 级别把**整个序列化后的握手**打进日志。对于一个远端工作区连接，这些字节里带着 bearer 令牌——它是作为 `Sec-WebSocket-Protocol` 的值传输的——以及你配置的每一个自定义请求头，而那正是 Cloudflare Access service token 所在的位置。于是最自然的排查动作（调高[日志级别](/zh/reference/settings/logs)、复现问题、把日志附到问题反馈里）会把凭据一并送出去。

从 **0.28.2** 起，这一行在**级别过滤器被查阅之前就已经被丢掉**——不是降到某个你还能再调回去的级别，因为这里没有什么详略可权衡：它只要打印，就一定打印出一个令牌。任何语法的 `CODEG_LOG` 指令都无法把它找回来。帧级别的 trace 不受影响，确有需要时依然可用。如果你手上还有此前排查连接时留下的日志，请把它们视作含有令牌，并轮换该令牌。
:::

这一拆分最明显地体现在备份上：正因为你的 [Git 和聊天令牌](/zh/reference/settings/version-control)存放在密钥环中，**桌面备份无法包含它们**（恢复后你需要重新输入），而服务器的 `tokens.json` *则是*其备份的一部分。而数据库那一组无论如何都会跟着归档一起走 —— 这正是[口令](#backups)存在的意义。

## 将 Codeg 暴露到网络 {#exposing-codeg-to-the-network}

默认情况下 Codeg 不监听任何人 —— 桌面应用不开放任何端口。有两个功能会有意改变这一点，且二者都由你掌控：

- **[Web 服务](/zh/reference/settings/web-service)**将桌面应用变成一个浏览器可访问的服务器。它绑定到**所有网络接口（`0.0.0.0`）**，因此任何能在该端口路由到你机器的人都能访问登录页 —— 这正是它**由一个访问令牌把关**的原因。把那个令牌当密码对待：保持其强度，并在你于不受信任的网络上用完后停止该服务。
- **[独立服务器](/zh/getting-started/deployment)**在设计上就是同样的思路，同样由令牌把关。

[原生移动客户端](/zh/getting-started/installation#mobile-apps)会通过上述两道入口之一连接。明文 HTTP 只应在受信任的局域网中使用；当流量需要跨越不受信任的网络时，请使用 HTTPS、VPN 或可信隧道。

对于企业网络，**[网络代理](/zh/reference/settings/system)**会将 Codeg 的所有出站流量 —— 智能体调用、git、更新 —— 都经由你指定的代理路由，从而使出口流量遵循你所在组织的政策。

### 自动处理的 webhook {#webhooks-for-auto-processing}

仓库面板的 [webhook 触发](/zh/guide/repository#set-up-the-webhook)由这两道入口中的任意一道应答，且**不需要访问令牌**，因为没有哪个 forge 能发送令牌。`POST /api/forge_webhook` 在桌面应用的 Web 服务和 `codeg-server` 上同样是公开的，改由推送自己来证明身份：GitHub、Gitea 和 Forgejo 用对请求体的 HMAC 签名，GitLab 则直接带上 secret token 本身，再以恒定时间与接收推送的那些文件夹的 webhook 密钥比对——这一切都发生在解析请求体、或对它做任何其他处理之前。

通过验证的推送只能做一件事：对一个你已设置好的仓库启动一次扫描，而这次扫描会用你自己的账户从 forge 的 API 读取每一个工作项。推送请求体里的任何内容都不会变成任务，也不会到达智能体。因此有两处局限没有看上去那么要紧：没有防重放保护——重放的推送最多只能再启动一次扫描；以及一个未签名的请求，会在其签名被检查之前就得知是否有*任何*文件夹在接收 webhook 推送。请求体上限为 2 MiB。

webhook 密钥未加密地存放在数据库里，任何已登录的客户端都能把它读回来。像对待访问令牌一样对待它；一旦泄露，就用**重新生成密钥**换掉它。

## 备份 {#backups}

一份[备份](/zh/reference/settings/system)是你数据的可移植副本，因此要把该文件本身当作敏感物对待。Codeg 对此毫不含糊：一个**未加密**的归档会以**明文**包含你的机密（API 密钥、令牌）。在导出时设置一个**口令**来加密它 —— 只是别弄丢那个口令，因为加密的备份若没有它便无法恢复。无论哪种方式，都请把该文件存放在你信任的地方。

## 值得了解 {#good-to-know}

- **没有遥测，就是没有。** Codeg 中不存在分析或追踪 SDK —— 没有任何东西衡量或上报你如何使用它。
- **你是唯一的服务器。** 无论你运行桌面应用还是自行托管，你的数据都留在你所掌控的硬件上；不存在数据流经的、由 Codeg 运营的后端。
- **模型提供商才是真正的出口。** 离开你机器的最重要的东西，是你的智能体发送给其模型提供商的内容 —— 而那是需要用你在[模型提供商](/zh/guide/authentication)下设定的密钥去权衡的、提供商的数据政策。
- **智能体在有风险的操作前会询问。** 通过 ACP 驱动，智能体会为敏感操作请求**权限**，而不是悄无声息地执行 —— 这是一项你能在对话中看到并回应的控制。
- **你的屏幕要逐个窗口地由你主动开放。** 电脑操作默认关闭；即使开启，智能体也只能读取你共享的窗口，只能在你共享为可操作的窗口里动手——一个按钮或一个快捷键就能结束这一切。→ [电脑操作](#computer-use)
- **哪些机密搭载在数据库里，值得心里有数。** Git、forge 和聊天渠道令牌进入操作系统密钥环（或服务器的 `tokens.json`）。模型提供商密钥、智能体环境变量、远端工作区令牌、Web 服务令牌以及 webhook 密钥，则未加密地存在 SQLite 文件里——在把数据目录复制到任何地方之前，请先看[这份细分](#where-secrets-are-kept)。
