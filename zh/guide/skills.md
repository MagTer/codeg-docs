# 技能

**技能**是一个可复用的指令文件——一个带有名称、描述和步骤的 Markdown `SKILL.md`——智能体可以按需将它拉入一项任务。[MCP 服务器](/zh/guide/mcp)为智能体提供新的*工具和数据*，而技能则赋予它*专业知识*：如何进行一次严谨的代码审查、如何设计一个实验、如何从零构建一个 `.docx`。你在对话中通过键入 `/` 并从菜单中选取来调用某个技能。

技能是智能体自己的功能——每个受支持的智能体都从它自己的技能目录中读取它们。Codeg 是其上的管理层，它为你提供两种把技能放到那里的方式：

- **技能包**——Codeg 附带的精选捆绑包（**Experts**、**Science**、**Office**），外加**界面渲染**——让智能体能[用卡片、表格和图表作答](#cards-tables-and-charts-in-replies)的那一个技能。你为选定的智能体启用某个包的技能，Codeg 便会将它们链接进去。
- **你自己的技能**——手动编写一个 `SKILL.md`。在共享存储中编写一次，然后从与技能包相同的矩阵里为各个智能体启用它（**技能包 → 自定义**）；或者直接写入某个智能体自己的目录（**技能**）。

无论哪种方式，结果都相同：技能会出现在该智能体的 `/` 菜单中，随时可以调用。两者都位于相邻的设置界面下——**技能包**和 **Skills**——本页接下来将依次介绍。

## 启用一个精选技能包 {#enable-a-curated-skill-pack}

打开**设置 → 技能包**。这是一个带标签页的中心——**专家**、**科学研究**、**办公工具**、**界面**和**自定义**——管理着三个由 Codeg 管理的精选捆绑包、界面渲染技能，以及你自己的技能（[见下文](#custom-skills)），它们共享同一个**中央存储**（`~/.codeg/skills`）和同一套启用模型：

| 技能包 | 其中有什么 | 深度 |
| ---- | ------------ | ----- |
| **专家** | 一个软件工程工作流库（取自开源的 *superpowers* 合集）——按**发现**、**规划**、**执行**、**质量**、**调试**、**审查**和**元**分组。 | 开箱即用 |
| **科学研究** | 一个研究工具箱——**构思**、**设计**、**分析**、**可视化**、**评估**和**文献**。 → [科学研究](/zh/guide/research) |
| **办公工具** | 用于创建和编辑 `.docx`、`.xlsx` 和 `.pptx` 的文档技能，由内置的 **officecli** 工具驱动。 → [Office 文档](/zh/guide/office) |
| **界面** | 只有一个技能——**界面渲染**，它教智能体在 Codeg 的聊天里用可交互的卡片、表格和图表作答。 → [见下文](#cards-tables-and-charts-in-replies) | 开箱即用 |

### 技能与智能体矩阵 {#the-skill-and-agent-matrix}

每个标签页都显示一个网格：技能在侧边（按类别分组），你的智能体在顶部横排——凡是确实会从 Codeg 能写入的位置读取技能的智能体都在其中。除 ZCode 之外，每一个内置智能体都在这里——ZCode 没有可供 Codeg 填充的技能文件夹；Kiro CLI、TRAE CLI 和 Command Code 是在 0.36 和 0.37 中新加入网格的，它们都只接受 `<id>/SKILL.md` 形式的文件夹。勾选一个单元格即可为该智能体启用该技能，取消勾选则将其移除。一切都可批量操作：

- 一个技能的 **⋯** 菜单可以一次性在**每个智能体**上启用或禁用它。
- 一个智能体的列标题则相反——一次性处理某个智能体的**每个技能**。
- **选择**若干技能（那些复选框），即可为选定的智能体子集切换选定的一组技能，而右上角的**批量**菜单——*全部启用（可见）* 或 *全部禁用（可见）*——可切换整个网格。
- 点击一个技能的名称可打开一个**预览抽屉**——它完整的 `SKILL.md`，外加一个按智能体的开关列表。

启用是即时且可撤销的；批量禁用会先征询确认，因为那是破坏性的方向。

### 启用究竟是如何运作的 {#how-enabling-actually-works}

中央存储是唯一的事实来源。当你为一个智能体启用某个技能时，Codeg 会从该智能体的技能目录放置一个指向中央副本的**符号链接**（在 Windows 上是*联接*）——因此没有任何东西被复制，也不存在记录启用状态的单独数据库：链接要么存在，要么不存在。如果你想查看，工具栏中的**打开中央文件夹**按钮会显示出 `~/.codeg/skills`。

一个单元格并不总是简单的开/关。你可能会看到：

- **已阻止**——一个同名的真实文件夹已存在于该智能体的技能目录中，因此 Codeg 不会覆盖它。请移动或重命名它，然后再启用。
- **链接至他处**——该名称已经是一个链接，指向 Codeg 存储之外的某个地方。
- **复制模式** *（琥珀色圆环）*——文件系统拒绝了符号链接，因此 Codeg 改为复制了这些文件。它仍然有效；只是不会就地自动更新。

::: tip 技能包会自我更新
Experts（以及任何内置技能）都烘焙进了 Codeg，并会在你升级时被重新提取到中央存储——因此已启用的技能无需你操作即可保持最新。就地编辑一个 Experts 或 Science 技能，Codeg 会将其标记为**用户已修改**并保留你的版本。**界面渲染**是个例外：只要它与 Codeg 附带的那份不一致，Codeg 就会重写它，因此在它上面做的编辑留不下来。Science 技能可能带有**需要密钥**或**需要设置**徽标——它们能正常链接，但技能本身在运行前需要一个 API 密钥或一个 Python 环境；参见该技能自己的说明以及[凭据存放位置](/zh/guide/authentication#where-credentials-are-stored)。
:::

### 在共享存储中编写你自己的技能 {#custom-skills}

最后一个标签页**自定义**，是你*自己的*技能在同一个中央存储中的落脚处——因此你只需编写一次，就能从矩阵里为任意智能体启用它，而不必在每个智能体的目录里各写一遍。它的行为与技能包标签页一样（同样的网格、同样的符号链接接入），只不过这些技能由你自己编辑。

在自定义标签页中，你可以：

- **新建、编辑、复制和删除**技能，它们保存在 `~/.codeg/skills` 下。
- **从文件夹导入**——引入一个已有的技能目录。在桌面端这是原生文件选择器；在网页或远程工作区，则是服务器端的目录浏览器。
- **从某个智能体导入**——一次性把某个智能体自己全局技能目录里的多个技能拉进共享存储。该选择器只列出该智能体*自己的*技能；任何已由 Experts、Science 或 Office 技能包提供的内容——或 Codeg 自己的界面渲染——都会被过滤掉，因此你不会重复导入内置技能。
- 你也可以自己把一个技能文件夹丢进 `~/.codeg/skills`，它会在下一次**刷新**时出现——凡是不属于 Experts、Science 或 Office 技能包、也不是 Codeg 自己那份界面渲染的，都算作自定义技能。

自定义技能一旦进入存储，就像技能包里的技能一样按智能体启用它——在[矩阵](#the-skill-and-agent-matrix)里勾选它的单元格，或用 **⋯** 和列菜单批量铺开。

## 回复中的卡片、表格与图表 {#cards-tables-and-charts-in-replies}

自 **0.35.0** 起，智能体的回答可以不止是文字：一条回复可以带上**可交互的卡片和表格**——自 **0.35.1** 起还有图表——在流式输出的同时直接画在对话里。让智能体写出它们的，是一个技能——技能包**界面**标签页上的**界面渲染**。把它们画出来的，是 Codeg 的聊天区，对每个智能体都一样，无需开启任何东西。

**按智能体启用。** 这个标签页和其他几个一样，是同一套技能与智能体矩阵，只有一行——*生成式界面 → 界面渲染*——凡是从 Codeg 能写入的位置读取技能的智能体各占一列，自定义智能体也包括在内。勾选你想要的智能体；每个智能体都会在你启用之后新开的对话里获得这个技能。

**然后提出要求。** 以 `/ui-render` 开头写一条消息——在 Codex 里是 `$ui-render`——再说明你想看到什么：*"/ui-render 用表格列出这次改动的文件"*。或者直接要求用卡片、表格或图表来展示；拥有这个技能的智能体会在可视化布局有帮助时用上它，没有帮助时就用普通 Markdown 作答。这个技能还会要求它用**会话中的真实数据**来构建卡片，绝不编造数字，除非你要的就是一份示意稿。

它教给智能体的，是在回复里写一个 **`spec`** 代码块——一行行 JSON Patch，从一套 shadcn 组件目录里搭起一棵组件树：卡片、表格、标签页、折叠面板、徽标、提示框、进度条、表单输入框和按钮，以及七种图表——**面积图、柱状图、折线图、饼图或环形图、雷达图、径向图和散点图**。它是这样渲染的：

- **边流式输出边生长。** 回复还在写的时候，卡片就会逐步填充；一行尚未完整到达的内容会先被搁置，而不是画成半截。
- **只认智能体自己的回复正文。** 你粘贴进自己消息里的 `spec` 代码块，或出现在某个工具输出里的，都仍然是代码块——无法解析或渲染失败的也一样，它会退回去显示源码。
- **图表跟随你的主题**，悬停时显示数值，在回复流式输出期间保持静止；只有开启了[聊天区域动画](/zh/reference/settings/appearance#chat-animations)，它们才会有动画。自 **0.35.1** 起，卡片平铺在消息里，不带阴影。
- **输入框和按钮只作用于卡片内部。** 它们没有接回智能体或应用，所以填写一个字段或按下一个按钮，改变的只是这张卡片自己的状态。链接的打开方式与对话里的任何链接相同。
- **画出来的就一直在。** 渲染并不依赖这个技能，所以即使你禁用了它，较早回复里的卡片仍会照常渲染，无论是哪个智能体写的。

这个技能本身归 Codeg 所有：只要它的 `SKILL.md` 与 Codeg 附带的那份不一致，就会按后者重写，因此对它做的修改会丢失。中央存储里一个**你自己的**、名为 `ui-render` 的技能则绝不会被动到——标签页会提示这个名字已被占用，给该行标上**名称被占用**，并请你先在**自定义**标签页把你的那个改名，内置的这个才能启用。某个智能体技能目录里一个同名的真实文件夹，只会阻止该智能体那一格，与[技能包里的技能](#how-enabling-actually-works)遇到这种情况时一样。

::: info 从 0.35.0 升级而来
**0.35.0** 把这项功能放在一个总开关后面——*启用 json-render 生成式界面*——当时这个技能叫 **json-render**。**0.35.1** 用按智能体的矩阵取代了这个开关，并给技能改了名：如果你当时打开了开关，那么已经装有 json-render 的智能体会在你升级时换上 ui-render；如果开关是关着的，Codeg 的 json-render 链接会被清理掉。无论哪种情况，你自己的 json-render 技能都不会被动。
:::

## 编写你自己的技能 {#write-your-own-skill}

**Skills** 界面以另一种方式编写技能，与上面的自定义标签页不同：你直接写入**某个智能体自己的技能目录**（全局或按项目），而不是共享存储——没有矩阵，技能只归该智能体所有。当某个技能专属于某个智能体或某个项目时用它；当你想编写一次并共享给每个智能体时，用**技能包 → 自定义**。

对于任何不在任何技能包中的技能——一项内部约定、一个你反复执行的工作流——打开**设置 → Skills**并直接编写它。

选择一个**受管目标**（只有真正支持技能的智能体才会出现在下拉列表中），然后选择一个**范围**：

- **全局**——智能体的主技能目录（Claude Code 的是 `~/.claude/skills`），在每个文件夹中都可用。
- **文件夹**——一个项目范围的目录（`{folder}/.claude/skills`），仅在你于该文件夹中工作时才出现。从你在 Codeg 中打开过的文件夹列表里选择该文件夹。

点击**新建技能**，为它指定一个 id（它将成为磁盘上的文件或 `{id}/SKILL.md` 目录，以及你将用来调用的 `/` 名称），然后编写正文。编辑器是分栏的：一个 Markdown 源码窗格，以及一个**实时预览**，后者会渲染内容并提取出 YAML 前置字段。一个 `SKILL.md` 只不过是前置内容加上一段步骤：

```markdown
---
name: pr-review
description: Review a pull request for correctness, tests, and style
---

When asked to review a PR:
1. Read the diff and summarize the intent in one line.
2. Check each changed file for logic errors and missing tests.
3. Flag anything that breaks the project's conventions.
```

保存后，它会与技能包安装的技能并列出现。在列表中，你可以**预览**、**编辑**、**打开它所在的文件夹**，或**删除**它。作为系统一部分附带的技能会被标记为**只读**——你可以阅读它们，但不能更改。因为你是直接写入智能体自己的技能目录，所以这就是智能体的原生技能格式；Codeg 只是为它提供了一个编辑器和一个预览。

## 在对话中调用技能 {#invoke-a-skill-in-a-conversation}

已启用的技能会在你需要它们的那一刻出现在 composer 中。键入 **`/`**，它们就会紧挨着斜杠命令出现在自动补全里——选取一个即可将它放入你的消息。*（Codex 使用 **`$`** 而非 `/`，以符合它自己的约定。）* 大多数智能体会自己在那里列出它们的技能。有两个由 Codeg 从设置 → Skills 所管理的那些文件夹中读取：Codex，列在它的 `$` 列表里；以及自 **0.36.0** 起的 Google Antigravity——它自己只列出寥寥几个命令——技能追加在它 `/` 菜单里这些命令之后。名称里带冒号的命令，比如 Qoder 的 `/sites:sites-building`，自 **0.37.0** 起会被当作一条命令来识别，并按原名原样送达智能体。自 **0.35.0** 起，带参数的命令会按智能体自己的描述显示后面该填什么——Codex 的 `/review-branch` 显示的是 *branch name*——这份列表里、**+** 菜单的*斜杠命令*里以及自动化编辑器里都是如此；选中它，插入的仍然只是命令本身。**+** 菜单还带有三大技能家族——Experts、Office 和 Research——的快捷方式，让你无需记住名称即可找到常用技能。

有两点需要了解：

- 一个**未为当前智能体启用**的技能会显示为锁定状态——先为该智能体启用它（在技能包或技能中），它就会亮起来。
- 你编写的**文件夹范围**技能仅在你于其所在文件夹中工作时才出现；全局技能则始终存在。

## 须知 {#good-to-know}

- **技能是按智能体划分的，而非按 Codeg 划分。** 为 Claude Code 启用一个技能并不会为 Codex 启用它——这正是那个矩阵的意义所在。你可以为任意多个智能体开启同一个技能。
- **更改在下一个会话生效。** 技能会在智能体启动一个对话时被读取；对于一个已经打开的对话，**重新连接以应用**会在不丢失历史的情况下加载它。→ [配置智能体](/zh/guide/agents#configure-an-agent)
- **禁用是安全的，也是彻底的。** 它从不触碰中央副本，另一个智能体自己文件夹里的链接也原封不动。它移除的是 Codeg 在这个智能体读取的**每一个**全局技能文件夹里放的链接——其中包括共享的 `~/.agents/skills`——因此，如果另一个智能体也在从那个共享文件夹读取这个技能，它会在两边一起消失。彻底移除一个内置技能则会一次性把它从所有智能体中删除。
- **在服务器上运作方式相同。** 两个设置界面都在浏览器版本中；技能位于 Codeg 运行所在的机器上。
- **自定义的 Pi 智能体目录不参与。** 如果你已把 Pi 指向一个非默认的 `PI_CODING_AGENT_DIR`，它就不受共享存储管理，也不会作为目标出现。→ [智能体之间有何不同](/zh/guide/supported-agents#how-agents-differ)
- **自定义智能体必须声明技能放在哪里。** Codeg 无法猜到你自己注册的智能体从何处读取技能，因此只有当你在它的设置卡片上勾选**共享的 `.agents/skills` 存储**或指定一个**专属技能目录**之后，它才会作为一列出现。在那之前它会被排除在外——因为那里的链接只会失败。→ [自定义智能体](/zh/guide/custom-agents#give-it-skills)
